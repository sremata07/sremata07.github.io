## Hindsight isn't 2026

Having already taken this class last semester, I thought that redoing all of the TypeScript assignments would be incredibly easy, but I was sorely mistaken. 

The most difficult thing was expecting all of my TypeScript experience to just come back to me, and then I sit down to code, and I realize that I don't remember how to use TypeScript. I thought I would be able to look back on my memories and cruise through, but as that saying goes: "if you don't use it, you lose it."

## What I learned and relearened 

One thing I learned was how nice TypeScript really is. Since I last used TypeScript, I learned how to use C. To me, C is very confusing and I felt relief using TypeScript again with how familiar and simple it is. To give an example, here's how I learned to print a string combined with an integer in C vs how I would do it in TypeScript:

C:
```
int main(void) {
  double number = 1;
  printf("The number is: %f", number);
  return 0;
}
```

TypeScript:
```
let number = 1;
console.log("The number is: " + number);
```

It could just be me, but I find the way C does something as simple as this to be vastly more complicated than how TypeScript does this. Now what I had to relearn was the syntax for TypeScript. For example, to print something it's `console.log()` and not something like `system.out()` or `print()`. I distinctly remember staring at some code I wrote for an assignment and wondering why I was getting an error when I was trying to print something it was because I was using `system.out()`.

## TypeScript is good

But why? It's in the name, it's because of the types added in TypeScript. Javascript has the `let` and `const` variable declarations, but then TypeScript allows you to add types to this variables. `let number: number1 = 0` is now a number variable, but then TypeScript can assume types of variables like so: `let number2 = 0`. Now, number1 and number2 are both number variables with the value of '0'.
